### 建議（不影響判定）

1. **建議｜ch10.sh 第 7 步（`scenario_agent.py` 的 `main`／`build_prompt`）**：測試時模型其實有回應，但 `extract_json` 從第一個 `{` 取到最後一個 `}`，遇到 `Extra data` 就失敗，結果改用範例。這樣第 7 步的輸出和第 6 步的離線預演一模一樣，學習者看不到真實模型會不會掉進陷阱，等於練習 2 最有價值的部分落空。改法（不動 `llm_agent.py`）：在 `scenario_agent.py` 裡改用 `from llm_agent import ask, ask_json`，`main()` 在 `ask_json` 拋 `ValueError` 時不要再呼叫一次模型，而是改成「只呼叫一次 `ask`，自己用 `json.JSONDecoder().raw_decode(text[text.find("{"):])` 取第一個物件」──也就是一開始就呼叫 `ask(prompt + 只輸出一個 JSON 物件……)`，再用 `raw_decode` 解析，解析失敗才用 FALLBACK。這樣維持只呼叫 1 次。最少也要照測試紀錄的建議，在 `build_prompt` 加一行「只輸出一個 JSON 物件，不要在 JSON 前後加任何說明文字或程式碼區塊」。
2. **建議｜ch10.sh 第 8 步重點 2（第 659 行）**：「前 1% 拿走約四成以上星標」，但固定種子下實際是 38.8%，不到四成。改成「約四成」（和教練稿第 2 步的「四成上下」一致）。
3. **建議｜coach-ch10.txt 整體**：K142 範本每步後面有一段「【第 N 步結果】」，朗讀實際結果再說「說繼續，進入第 N 步」。本章教練稿只有步驟說明，結果是混在說明裡預告的。這不在本次審查項目內，若工廠格式要求和範本完全一致，可以補上各步結果段（第 7 步因為模型結果不固定，可以寫成「看總分與判錯的路徑」）。
