## 建議（不構成退回）

1. **建議｜ch01.sh 第 155 行（第 5 步的標記）**：條件是 `g.allowed and not i.allowed`，所以合約只出 WARN 時也會標成「合約擋下」。這次測試的 patch_repo 那行就是這樣，學員會誤以為 WARN 等於擋下。改法：`mark = ("  ← 閘道放行、合約擋下" if i.decision.value == "deny" else "  ← 閘道放行、合約警告") if g.allowed and not i.allowed else ""`。第 3 步的 5 筆 intent 都含 investigate，不會遇到這個情況，可以不改。
2. **建議｜爬坡（hill climbing）講得太輕**：「這章在講什麼」第 3 條說爬坡要「有邊界、看得見、可回退、有證據」。目前只在第 8 步的一句關鍵句裡出現，第 7 步雖然用 `hill_climb_governance` 重算了雜湊，卻沒有把內容印出來。可以在第 7 步多印 `a["hill_climb_governance"]` 的摘要，再請教練稿第 7 或第 8 步用一句話解釋「爬坡＝代理在計畫、工具、程式之間做局部搜尋，harness 負責定邊界」。
3. **建議｜「為什麼不能只信提示詞」沒有明講**：本章開頭的觀念「不能因為提示詞寫得小心、模型有把握就信任」，可以在教練稿第 1 步開頭補一句。
4. **建議｜ch01.sh 第 192 行（第 7 步的防呆）**：如果 cli 失敗、stdout 是空的，`json.loads` 會直接丟出 Traceback。可以先檢查 `proc.returncode` 和 `proc.stdout`，失敗時印出 `proc.stderr`。
5. **建議｜`__pycache__`**：在 `HarnessLab/` 裡 import 會產生 `__pycache__`（ch02 範本也一樣）。想讓 HarnessLab 完全不被動到，可以在 `run()` 加上 `PYTHONDONTWRITEBYTECODE=1`。
