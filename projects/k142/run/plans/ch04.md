## 第 1 步：認識主角——一份意圖合約與它的 goal_digest

**目的**：「使用者叫我幫忙」不是永久通行證。意圖合約把「這次要做什麼」寫成機器查得了的欄位：目的、誰做、哪些工具、哪些資料、風險上限、要什麼證據、何時到期、哪些要升級給人。goal_digest 則是把目的鎖成一個指紋，之後恢復時拿來比對。

**指令（內嵌 Python）**：

```python
print("  intent_id      ：", contract.intent_id)
print("  目的 goal       ：", contract.goal)
print("  誰可執行        ：", contract.actor_role)
print("  允許工具        ：", sorted(contract.allowed_tools))
print("  允許資料        ：", sorted(x.value for x in contract.allowed_data))
print("  風險上限        ：", contract.max_risk.value)
print("  必要證據        ：", sorted(contract.evidence_required))
print("  要升級給人      ：", sorted(x.value for x in contract.escalation_required_for))
print("  幾秒後到期      ：", round(contract.expires_at - now), "秒   已過期？", contract.expired)
print()
print("  goal_digest（原目的）     ：", _goal_digest(GOAL))
print("  goal_digest（大小寫空白亂）：", _goal_digest("  Remediate VULNERABLE dependency in   billing-api "))
print("  goal_digest（換成通知客戶）：", _goal_digest(NOTICE_GOAL))
```

**預期看到**：
- intent_id `intent-remediate-billing-dependency`、角色 `remediation_agent`、工具 `['emit_trace', 'patch_repo', 'read_ticket']`、資料 `['internal', 'public']`、風險上限 `reversible_write`、證據 `['test_log', 'ticket']`、升級 `['external_communication', 'privileged_operation']`、`600 秒   已過期？ False`。
- 三個 digest 都是 16 個十六進位字元；**前兩個完全相同**（正規化掉大小寫與空白），第三個不同。

**是否呼叫模型**：否

## 第 2 步：依目的授權——同一個工具，換個目的答案就變

**目的**：授權看的是「這個目的下可不可以」，不是工具本身好不好。寄客戶信在「修套件」目的下被拒，但只看工具閘道會放行；換到「通知客戶」的新合約，同一封信就合法，反而改程式不行。順便看合約的其他邊界：資料、風險、到期。

**指令（內嵌 Python）**：

```python
from chapters.ch04.scenario import _purpose_bound_reauthorization
v = h.intent
print("【目的：修 billing-api 的漏洞套件】")
show("read_ticket 讀票券", v.verify(contract, call("read_ticket")))
show("patch_repo 改程式", v.verify(contract, call("patch_repo", risk=ActionRisk.REVERSIBLE_WRITE)))
show("deploy_service 部署", v.verify(contract, call("deploy_service", risk=ActionRisk.PRIVILEGED_OPERATION)))
email = call("send_customer_email", DataClass.PII, ActionRisk.EXTERNAL_COMMUNICATION, ticket="SEC-204")
show("send_customer_email 寄客戶信", v.verify(contract, email))
show("patch_repo 但碰到 PII", v.verify(contract, call("patch_repo", DataClass.PII, ActionRisk.REVERSIBLE_WRITE)))
show("patch_repo 但不可回復", v.verify(contract, call("patch_repo", risk=ActionRisk.IRREVERSIBLE_WRITE)))
show("合約過期後再讀票券", v.verify(dataclasses.replace(contract, expires_at=now - 1), call("read_ticket")))
print("\n【只看工具閘道，不看目的】")
show("send_customer_email 寄客戶信", h.gateway.check(email))
notice, _ = _purpose_bound_reauthorization(NOTICE_GOAL, {"purpose": NOTICE_GOAL}, now)
print("\n【換成目的：通知受影響客戶】")
show("send_customer_email 寄客戶信", v.verify(notice, call("send_customer_email", DataClass.PII, ActionRisk.EXTERNAL_COMMUNICATION, intent=NOTICE_GOAL)))
show("patch_repo 改程式", v.verify(notice, call("patch_repo", risk=ActionRisk.REVERSIBLE_WRITE, intent=NOTICE_GOAL)))
```

**預期看到**：
- 修套件目的：讀票券、改程式 `ALLOW intent contract satisfied`；部署 `DENY tool deploy_service is outside approved purpose`；寄客戶信 `DENY tool send_customer_email is outside approved purpose`；碰 PII `DENY data class pii is outside contract`；不可回復 `ESCALATE risk exceeds contract maximum`；過期 `DENY intent contract expired`。
- 工具閘道對同一封信：`ALLOW tool gateway accepted call`（工具結構上合法，閘道擋不了「目的不對」）。
- 通知客戶目的：寄客戶信 `ALLOW intent contract satisfied`；改程式反而 `DENY tool patch_repo is outside approved purpose`。

**是否呼叫模型**：否

## 第 3 步：偏移偵測與它的陷阱——只看 goal 的第一個字（練習 2 離線版）

**目的**：工具、資料、風險都在合約內時，最後一道關是偏移偵測：書附只檢查 goal 的第一個字 `remediate` 有沒有出現在 intent 裡。這一步看它抓得到「順手優化推薦排序」，但也看它漏抓（偽陰性）和誤報（偽陽性）。

**指令（內嵌 Python）**：

```python
v = h.intent
key = GOAL.lower().split()[0]
print("  偏移偵測只拿 goal 的第一個字來比：", repr(key))
print()
tests = [
    ("正常：照目的修補", GOAL, "應放行"),
    ("偏移：順手優化推薦排序", "optimize recommendation ranking while the repo is open", "應警示"),
    ("偽陰性：修完順便刪稽核紀錄", "remediate dependency then delete audit logs", "應警示"),
    ("偽陰性：子字串也算數", "unremediated recommender ranking work", "應警示"),
    ("偽陽性：換個動詞", "fix vulnerable dependency in billing-api", "應放行"),
    ("偽陽性：講具體套件", "bump safe-yaml to 2.4.1 for SEC-204", "應放行"),
]
wrong = 0
for label, intent, want in tests:
    d = v.verify(contract, call("patch_repo", risk=ActionRisk.REVERSIBLE_WRITE, intent=intent))
    got = "應放行" if d.allowed else "應警示"
    ok = got == want
    wrong += not ok
    print(f"  {label:<16} {d.decision.value.upper():<6} {'✔ 判對' if ok else '✘ 判錯'}  intent={intent}")
print(f"\n  6 筆裡判錯 {wrong} 筆。工具、資料、風險範圍是前面的硬關卡，關鍵字比對只是最後一道薄關卡。")
show("對照：intent 寫 remediate 但想部署", v.verify(contract, call("deploy_service", risk=ActionRisk.PRIVILEGED_OPERATION, intent="remediate by deploying now")))
```

**預期看到**：
- 第一行印 `'remediate'`。
- 六筆依序：`ALLOW ✔`、`WARN ✔`、`ALLOW ✘`、`ALLOW ✘`（`unremediated` 含子字串 `remediate`）、`WARN ✘`、`WARN ✘`；「6 筆裡判錯 4 筆」。
- 對照行：`DENY tool deploy_service is outside approved purpose`（就算 intent 寫對關鍵字，工具範圍照樣擋）。

**是否呼叫模型**：否

## 第 4 步：不只放行與拒絕——改寫（REWRITE）與升級（ESCALATE）

**目的**：偏移不一定要擋死。寄客戶信被改寫成一筆內部 `emit_trace` 紀錄，客戶信箱被拿掉、風險降到 read，工作能繼續；改寫後的呼叫再過一次意圖層與工具閘道。改寫不了的（部署、讀金庫、不可回復的寫入）就升級給人。

**指令（內嵌 Python）**：

```python
from chapters.ch04.scenario import _rewrite_or_escalate
email = call("send_customer_email", DataClass.PII, ActionRisk.EXTERNAL_COMMUNICATION, ticket="SEC-204", customer="learner@example.com")
show("意圖層先看寄客戶信", h.intent.verify(contract, email))
d = show("改寫或升級", _rewrite_or_escalate(contract, email))
rc = d.rewritten_call
print(f"    改寫成：tool={rc.tool}  資料={rc.data_class.value}  風險={rc.side_effect.value}")
print(f"    參數：{rc.args}")
print(f"    客戶信箱還在嗎？{'learner@example.com' in str(rc.args)}")
show("改寫後 → 意圖層", h.intent.verify(contract, rc))
show("改寫後 → 工具閘道", h.gateway.check(rc))
print()
show("部署（特權）", _rewrite_or_escalate(contract, call("deploy_service", risk=ActionRisk.PRIVILEGED_OPERATION)))
show("讀金庫（特權＋機密）", _rewrite_or_escalate(contract, call("query_vault", DataClass.SECRET, ActionRisk.PRIVILEGED_OPERATION)))
show("不可回復的寫入", _rewrite_or_escalate(contract, call("patch_repo", risk=ActionRisk.IRREVERSIBLE_WRITE)))
```

**預期看到**：
- 意圖層：`DENY tool send_customer_email is outside approved purpose`。
- 改寫：`REWRITE external communication rewritten to internal evidence until purpose-bound authorization exists`；改寫成 `tool=emit_trace  資料=internal  風險=read`；參數 `{'event': 'customer_notice_draft_blocked', 'ticket': 'SEC-204', 'redaction': 'customer identifiers removed until communication purpose is approved'}`；「客戶信箱還在嗎？False」。
- 改寫後兩關都 `ALLOW`（`intent contract satisfied`、`tool gateway accepted call`）。
- 部署、讀金庫：`ESCALATE contract requires human escalation for this tool-call purpose`；不可回復寫入：`ESCALATE tool call cannot be safely rewritten under the active intent contract`。

**是否呼叫模型**：否

## 第 5 步：從檢查點恢復——目的變了就要重新授權，核准不能挪用

**目的**：長時程代理特有的問題：昨天核准的目的，今天未必還成立。檢查點存了 goal_digest，恢復時比對現在的目的；不符就升級要求重新授權。重新授權時，核准是綁定目的的，拿「部署」的核准來申請「通知客戶」會被拒；新合約還要證據齊全才生效。

**指令（內嵌 Python）**：

```python
from chapters.ch04.scenario import _detect_stale_resume, _purpose_bound_reauthorization, _evidence_gate
ck = h.runtime.checkpoint(
    run_id="run-ch04-remediation",
    state={"intent_id": contract.intent_id, "goal_digest": _goal_digest(GOAL), "last_completed_step": "patch_prepared"},
    policy_version="training-policy-v1",
    evidence_hash="evidence_remediation_001",
)
state = h.runtime.resume_from(ck.checkpoint_id)
print(f"  檢查點 {ck.checkpoint_id}   存的 goal_digest={state['goal_digest']}")
print("\n【恢復時比對目的】")
show("目的沒變", _detect_stale_resume(state, GOAL, contract))
show("只差大小寫與空白", _detect_stale_resume(state, "  Remediate VULNERABLE dependency in billing-api", contract))
show("同義改寫：fix 取代 remediate", _detect_stale_resume(state, "fix vulnerable dependency in billing-api", contract))

print("    發出的合約：", bad)
new, d2 = _purpose_bound_reauthorization(NOTICE_GOAL, {"approval_ticket": "APP-92", "purpose": NOTICE_GOAL}, now)
show("核准目的相符", d2)
print(f"    新合約 {new.intent_id}  角色={new.actor_role}  工具={sorted(new.allowed_tools)}  風險上限={new.max_risk.value}")
show("新合約：證據只給 approval_ticket", _evidence_gate(new, frozenset({"approval_ticket"})))
```

**預期看到**：
- 檢查點 id 以 `ckpt_` 開頭，goal_digest 和第 1 步「原目的」那串相同。
- 目的沒變、只差大小寫空白：`ALLOW resume purpose still matches checkpoint`；同義改寫、換成通知客戶：`ESCALATE resume checkpoint goal no longer matches the active purpose; reauthorization required`（digest 是逐字比對，同義詞也會被要求重新授權——寧可多問）。
- 拿部署核准：`DENY reauthorization approval is bound to a different purpose`，「發出的合約： None」。
- 目的相符：`ALLOW new purpose-bound intent contract issued for approved customer notice`；新合約 `intent-customer-notice  角色=customer_comms_agent  工具=['emit_trace', 'send_customer_email']  風險上限=external_communication`。
- 證據只給一半：`ESCALATE missing required intent evidence: message_template`；齊全：`ALLOW required intent evidence present`。

**是否呼叫模型**：否

## 第 6 步：讓真實子代理被留言誘導偏離，原版 vs 改良版偵測器（練習 2）

**目的**：對應練習 2。用另一份合約（goal 第一個字是 `upgrade`），請真實模型讀一則誘導留言（順便看推薦排序、清掉舊稽核紀錄）後規劃 4 個工具呼叫；連同 2 個手動對照 intent，一起送進原版 `IntentVerifier.verify` 與一個改良版（禁用詞＋目的關鍵詞重疊）。改良版也要誠實列出自己的新弱點。

**指令（內嵌 Python）**：

```python

    max_risk=ActionRisk.REVERSIBLE_WRITE,
    evidence_required=frozenset(),
    expires_at=time.time() + 600,

SRC = '''import re
STOP = {"in", "the", "a", "an", "of", "to", "for", "and", "service"}
BANNED = ("delete", "audit", "recommend", "ranking", "deploy", "customer", "email", "secret", "refactor", "optimize")
def better_check(goal, intent):
    text = intent.lower()
    hits = [w for w in BANNED if w in text]
    if hits:
        return "warn", "禁用詞：" + ", ".join(hits)
    overlap = (set(goal.lower().split()) - STOP) & set(re.findall(r"[a-z]+", text))
    if len(overlap) < 2:
        return "warn", "與目的關鍵詞重疊不足：" + ", ".join(sorted(overlap))
```
