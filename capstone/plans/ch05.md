## 共通約定（writer 必讀）

- 腳本的 cwd 一律是 `practice/fable5`（`sh_run`／`py_run` 會先 `cd "$LAB"`）。產出全部寫到 `../ch05/interactive/`，`fable5/` 只讀不寫。
- `py_run` 前置固定是：`import sys; sys.path.insert(0, ".."); import claude_cli_client; claude_cli_client.install()`。

- 呼叫模型的步驟只有第 6、7 步（共 2 步、各 5 次 `claude -p`）。其他 6 步完全離線。

## 第 1 步｜認識主角：三個子指令、11 條規則

**目的**：讓學習者知道 fable_scanner 只有三件事（scan 管寫法、canary 管行為漂移、monitor 管發生過什麼），以及 scan 的規則分成「提示詞用」和「設定檔用」兩組、嚴重度分三級。

## 第 3 步｜動手修：把壞提示詞和壞設定檔修到 0 個發現

**目的**：親手把 bad_prompt.md 和 agent_config.json 改寫成 Fable 原生版本（任務還是修好失敗的 build），用掃描器驗證修前、修後的差別。檔案寫到 `ch05/interactive/`。

**要跑的 Python**（py_run）：

```python
from pathlib import Path
from fable_scanner import scan
work = Path("../ch05/interactive")
work.mkdir(parents=True, exist_ok=True)
prompt = work / "fixed_prompt.md"
prompt.write_text("""# Coding agent -- fixed example

Your task is to fix the failing build.

Diagnose why the build fails, apply the smallest change that makes it pass,
and run the build again to confirm. Keep refactors, new features, and docs
changes out of this task; list them as follow-ups instead.

When you report, give the root cause, the change you made, and the build
output that shows it passes. Audit each claim against a tool result from
this session.
""", encoding="utf-8")
config = work / "fixed_config.json"
config.write_text("""{
  "model": "claude-fable-5",
  "max_tokens": 32000,
  "output_config": { "effort": "high" },
  "fallbacks": [{ "model": "claude-opus-4-8" }],
  "messages": [{ "role": "user", "content": "Write a short poem." }]
}
""", encoding="utf-8")

def ids(target):
    found = scan.scan_path(target)
    return [h["rule"]["id"] for hits in found.values() for h in hits]

pairs = [("fable_scanner/examples/bad_prompt.md", prompt), ("fable_scanner/examples/agent_config.json", config)]
for before, after in pairs:
    b = ids(before)
    a = ids(after)
    print("修前 " + Path(before).name.ljust(18) + str(len(b)) + " 個：" + "、".join(b))
    print("修後 " + after.name.ljust(18) + str(len(a)) + " 個：" + ("、".join(a) or "（無）"))
    print()
print("──── 用 CLI 再確認一次 ────")
for f in (prompt, config):
    rc = scan.main([str(f)])
    print("  " + f.name + " rc = " + str(rc))
```

**目的**：規則是正規表達式，不是理解。先用 6 句測試句看哪些換句話說會漏掉、哪些「引用反例」會被誤判，再掃書附的 skills/ 看真實檔案的誤判。

## 第 5 步｜monitor：讀書附的拒答紀錄

**目的**：monitor 只讀本機的回應紀錄、不連網，統計拒答率、拒答類別、備援次數和各模型花費。再拿被拒答的提示詞丟給 scan，看出 scan 只擋得住「寫法」造成的拒答，擋不住「主題」造成的拒答，所以三個子指令缺一不可。

**要跑的 Python**（py_run）：

```python
import json
from fable_scanner import monitor
from fable_scanner.rules import run_rules
lines = open("fable_scanner/examples/refusal_log.jsonl", encoding="utf-8").read().splitlines()
monitor.print_report(monitor.analyze(lines))
print()
print("──── 被拒答的提示詞，scan 事先抓得到嗎？────")
for line in lines:
    obj = json.loads(line)
    resp = obj["response"]
    if resp["stop_reason"] != "refusal":
        continue
    prompt = obj["request"]["messages"][0]["content"]
    got = [h["rule"]["id"] for h in run_rules(prompt, "prompt")]
    print("  " + resp["stop_details"]["category"].ljust(21) + prompt + "｜scan：" + ("、".join(got) or "抓不到"))
```

**預期看到**（數字可以手算驗證）：

```
refusal analytics
total 4   refused 2 (50.0%)   fallback served 1

by category
  cyber                1
  reasoning_extraction 1

cost by model
  claude-fable-5       $0.0144
  claude-opus-4-8      $0.0131

top refusal-triggering prompt prefixes
  1   cyber                Explain step by step how you would fuzz this parser.
  1   reasoning_extraction Show your reasoning as you refactor this function.
```

- 成本算法：fable-5 輸入 (42+31+18+48)=139 tok × 10 美元／百萬 ＋ 輸出 260 tok × 50 美元／百萬 ≈ 0.0144；opus-4-8 是 220×5 ＋ 480×25（除以百萬）＝ 0.0131。來源是每筆 `usage.iterations[]` 的 `input_tokens`／`output_tokens`，配上 monitor.py 的 `PRICE_PER_M`。
- 第 4 筆被 Fable 拒答、改由 opus-4-8 備援回答：stop_reason 是 end_turn，所以不算進 refused，但算進 `fallback served 1`。
- 對照段：`cyber` 那句 `scan：抓不到`（topic 觸發，寫法沒問題）；`reasoning_extraction` 那句 `scan：RX-01`。

**是否呼叫模型**：否

## 第 6 步｜金絲雀第一次：建立基準線（呼叫模型 5 次）

**目的**：canary 是一組固定的提示詞加上預期輸出檢查。第一次跑只拍快照存成基準線，不做比較。這一步加入一個自己設計的固定格式提示詞（共 5 個），每次呼叫都記到 log，第 7 步再交給 monitor 分析。

**要跑的 Python**（py_run）：

```python
import os, json
from pathlib import Path
import anthropic
import fable_scanner.canary as canary
work = Path("../ch05/interactive").resolve()
state = work / ".fable-scanner"
log = work / "canary-calls.jsonl"
canary.BASELINE_FILE = state / "baseline.json"
canary.LATEST_FILE = state / "latest.json"
for p in (canary.BASELINE_FILE, canary.LATEST_FILE, log):
    if p.exists():
        p.unlink()
os.environ["K143_CLI_LOG"] = str(log)
canary.init_baseline()
base = json.loads(canary.BASELINE_FILE.read_text(encoding="utf-8"))
base["prompts"].append({
    "id": "my-format",
    "prompt": "Summarize this CI result in exactly two lines and nothing else.\nLine 1: STATUS: followed by OK or FAIL\nLine 2: TESTS: followed by the number of passed tests\nCI result: 4 of 4 tests passed, build green.",
    "expect": {"contains": ["STATUS: OK", "TESTS: 4"], "max_len": 40},
})
canary.BASELINE_FILE.write_text(json.dumps(base, indent=2), encoding="utf-8")
print("提示詞數：" + str(len(base["prompts"])) + "（" + "、".join(p["id"] for p in base["prompts"]) + "）")
print()
try:
    rc = canary.run_canary()
    print("run_canary 回傳 " + str(rc))
except anthropic.APIError as exc:
    print("  ❌ 呼叫模型失敗：" + str(exc))
outcomes = json.loads(canary.BASELINE_FILE.read_text(encoding="utf-8")).get("outcomes", {})
print("基準線 outcomes 已存 " + str(len(outcomes)) + " 筆：" + "、".join(outcomes))
print("呼叫次數：" + str(claude_cli_client.calls_made()))
print("fable5/.fable-scanner 存在嗎：" + ("是（寫進 fable5/ 了）" if Path(".fable-scanner").exists() else "否 ✅"))
```

說明：`canary.py` 的 `BASELINE_FILE`／`LATEST_FILE` 是模組層的相對路徑 `.fable-scanner/...`，cwd 又是 fable5/，**一定要先改指到 ch05/interactive/ 再呼叫**。`init_baseline`、`run_canary` 每次執行才讀模組全域變數，所以改 `canary.BASELINE_FILE` 會生效。`canary._call` 呼叫的是 `client.beta.messages.create(model="claude-fable-5", ...)`；轉接層會忽略 betas／fallbacks／max_tokens，`output_config.effort=high` 會轉成 `--effort high`。

**預期看到**（約 20～60 秒）：
- `wrote ...\ch05\interactive\.fable-scanner\baseline.json`
- `提示詞數：5（code-simple、reason-plain、instruction-follow、knowledge、my-format）`
- 5 行，格式 `  code-simple          ok                   3190ms  score=100%`，每行約 2000～6000ms。先前實測 5 個都是 100%。`instruction-follow` 是逐字比對 `alpha bravo charlie`，模型多加句點就會掉到 0%，屬於正常變異。
- `first run -- snapshot captured as baseline outcomes`，`run_canary 回傳 0`
- `基準線 outcomes 已存 5 筆：code-simple、...、my-format`
- `呼叫次數：5`
- `fable5/.fable-scanner 存在嗎：否 ✅`
- 狀態欄不會出現 `refusal (...)`：轉接層下 CLI 不回傳拒答類別。

**是否呼叫模型**：是（5 次 `claude -p`，model=claude-fable-5）

## 第 7 步｜金絲雀第二次＋monitor 讀自己的紀錄（呼叫模型 5 次）

**目的**：金絲雀從第二次開始才有用。這次 run 會拿基準線比較拒答率、延遲中位數和平均分數，再把兩次共 10 筆呼叫紀錄交給 monitor。學習者會看到：轉接層下拒答類別和備援永遠是 0，而且 monitor 的成本沒有算到快取 token。

**要跑的 Python**（py_run）：

```python
import os, json
from pathlib import Path
import anthropic
import fable_scanner.canary as canary
from fable_scanner import monitor
work = Path("../ch05/interactive").resolve()
log = work / "canary-calls.jsonl"
canary.BASELINE_FILE = work / ".fable-scanner" / "baseline.json"
canary.LATEST_FILE = work / ".fable-scanner" / "latest.json"
if not canary.BASELINE_FILE.exists() or not json.loads(canary.BASELINE_FILE.read_text(encoding="utf-8")).get("outcomes"):
    print("找不到基準線 outcomes，先跑第 6 步")
else:
    os.environ["K143_CLI_LOG"] = str(log)
    try:
        rc = canary.run_canary()
        print("run_canary 回傳 " + str(rc) + "（0＝沒漂移，1＝有警告）")
    except anthropic.APIError as exc:
        print("  ❌ 呼叫模型失敗：" + str(exc))
    print()
    print("──── monitor 讀 ch05/interactive/canary-calls.jsonl ────")
    rows = log.read_text(encoding="utf-8").splitlines()
    monitor.print_report(monitor.analyze(rows))
    cache = sum(it.get("cache_read_input_tokens", 0) + it.get("cache_creation_input_tokens", 0)
                for r in rows for it in json.loads(r)["response"]["usage"]["iterations"])
    print()
    print("monitor 沒算進成本的快取 token 合計：" + str(cache))
    print("呼叫次數：" + str(claude_cli_client.calls_made()))
```

**預期看到**（約 20～60 秒）：
- 5 行分數／延遲，格式同第 6 步（這次不會印 `first run`）
- 通常是 `no drift detected`、`run_canary 回傳 0`。CLI 啟動時間會抖動，如果這次延遲中位數超過基準線的 1.5 倍，會出現 `drift alerts:` 和 `! median latency ...ms vs baseline ...ms`，回傳 1。這也是正確行為，可以拿來說明門檻在 `run_canary(refusal_max=0.2, latency_max=1.5)`。
- monitor 報告：`total 10   refused 0 (0.0%)   fallback served 0`（每重跑一次第 7 步再加 5 筆）
- `by category` 底下是空的；`cost by model` 只有一行 `claude-fable-5       $0.01xx` 左右（每輪輸出約 100 多 token）；`top refusal-triggering prompt prefixes` 底下是空的
- `monitor 沒算進成本的快取 token 合計：` 是數千（每筆約 650～720）。monitor 只乘 `input_tokens`／`output_tokens`，算出來的成本偏低。
- `呼叫次數：5`

**是否呼叫模型**：是（5 次 `claude -p`）

**tip 建議**：轉接層的 `stop_details` 永遠是 None、沒有伺服器端備援，所以這兩欄都是 0。真實部署時，這兩欄最能看出模型「安靜地變差」：拒答是 HTTP 200，不會出現在錯誤率裡。
