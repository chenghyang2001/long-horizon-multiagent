# 子題 2：成本與資源控管：API 呼叫費用、速率限制、上下文長度與運算資源的監控

- 設定每日／每小時的 API 費用上限與預算警報，按代理分別記錄 token 用量，避免某個代理陷入迴圈而燒光預算。
- 遵守速率限制：用指數退避加隨機抖動重試，並以佇列或令牌桶控制多個代理的同時請求數，避免集體觸發 429 錯誤。
- 監控每個代理的上下文長度，接近上限前主動摘要或壓縮，並把長期狀態寫入外部檔案，不要無限堆疊對話紀錄。
- 善用提示快取、批次 API，簡單子任務交給較便宜的小模型，以降低 24 小時累積的總成本。
- 持續監看 CPU、記憶體、磁碟與日誌檔大小，設定日誌輪替與資源閾值告警，防止記憶體洩漏或磁碟寫滿導致程式中途崩潰。
