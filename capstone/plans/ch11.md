```python
import copy, json
from pathlib import Path
WORK = Path("../ch11/interactive").resolve()
HIST = WORK / "history.json"
THINKING_TYPES = ("thinking", "redacted_thinking")
PLACEHOLDER = "（此輪原本只有思考區塊，跨模型時已移除）"

def dumps(obj):
    return json.dumps(obj, ensure_ascii=False)

def prepare_history(messages, source_model, target_model):
    out = copy.deepcopy(messages)             # 回傳深拷貝，絕不改傳入的原物件
    if source_model == target_model:
        return out                             # 同模型：一個區塊都不動，連空的 thinking 也留著
    for m in out:
        if m.get("role") != "assistant" or not isinstance(m.get("content"), list):
            continue
        kept = [b for b in m["content"]
                if not (isinstance(b, dict) and b.get("type") in THINKING_TYPES)]
        if not kept:
            # 整則只剩思考區塊：留一個說明用的 text，因為 API 不收 content 為空的 assistant 訊息
            kept = [{"type": "text", "text": PLACEHOLDER}]
        m["content"] = kept
    return out

def count_thinking(messages):
    return sum(1 for m in messages if isinstance(m["content"], list)
               for b in m["content"] if b.get("type") in THINKING_TYPES)

def block_types(messages):
    rows = []
    for i, m in enumerate(messages):
        c = m["content"]
        kinds = [b["type"] for b in c] if isinstance(c, list) else ["(字串)"]
        rows.append("  " + str(i) + " " + m["role"] + "：" + "、".join(kinds))
    return rows

def load_history():
    if not HIST.exists():
        raise SystemExit("找不到 " + str(HIST) + "，請先跑第 2 步")
    return json.loads(HIST.read_text(encoding="utf-8"))
```

## 第 5 步：找缺口——「好心清洗」破壞同模型規則，linter 卻抓不到

1. **標題**：反例：日誌清洗順手刪掉空的思考區塊
2. **目的**：重現作者踩過的 400。很多日誌管線會「好心」濾掉內容為空的區塊，看起來比較乾淨，但同模型重放時，思考區塊只要被動過，下一輪就會 400。再拿 linter 檢查清洗後的請求，會發現它只管「跨模型帶思考」，抓不到這個錯，所以同模型這一側要靠自己的位元組比對。
3. **指令**（py_run，程式＝`REPLAY_PY` ＋ 下面這段）：
   ```python
   from migration.migration_linter import lint
   history = load_history()

   def naive_clean(messages):
       """錯誤示範：日誌管線常見的「好心清洗」——把空的 thinking 濾掉"""
       out = copy.deepcopy(messages)
       for m in out:
           if isinstance(m["content"], list):
               m["content"] = [b for b in m["content"]
                               if not (b.get("type") == "thinking" and not b.get("thinking", "").strip())]
       return out

   same = prepare_history(history, "claude-fable-5", "claude-fable-5")
   cleaned = naive_clean(same)
   print("同模型重放（claude-fable-5 → claude-fable-5）")
   print("  正確版與原歷史逐位元組相同：" + str(dumps(same) == dumps(history)))
   print("  清洗版與原歷史逐位元組相同：" + str(dumps(cleaned) == dumps(history)))
   print("  第 3 則 assistant：原本 " + "、".join(b["type"] for b in history[3]["content"])
         + " → 清洗後 " + "、".join(b["type"] for b in cleaned[3]["content"]))
   print("  → 思考區塊被改動，下一次呼叫 Fable 5 會 400 驗證失敗")
   print()
   req = {"model": "claude-fable-5", "output_config": {"effort": "medium"},
          "fallbacks": [{"model": "claude-opus-4-8"}], "messages": cleaned}
   print("把清洗版包成 Fable 5 請求交給 linter：")
   for field, sev, msg in lint(req):
       print("  " + sev + "  " + field + "｜" + msg[:60])
   print("  → linter 只警告「帶著思考區塊」（跨模型的事），沒發現空 thinking 被刪掉")
   print("  → 同模型這一側的驗證者是 json.dumps 位元組比對，不是 linter")
   ```
4. **預期看到**：

## 第 6 步：工具互相驗證——用第 7 章 linter 檢查跨模型前後

1. **標題**：交叉驗證：處理後的 messages 警告消失
2. **目的**：把跨模型處理前、處理後的歷史各包成一個以 Opus 4.8 為目標的請求本體，交給 `lint()` 跑，處理後 messages 警告應該消失，整個請求是 clean。另外看 fallback_credit 的註解，它就是 linter 警告裡那句「除非 exact-body 兌換另有要求」的出處：手動兌換備援額度的時候本體要完全相同，那是唯一不能剝的情況。
3. **指令**（py_run，程式＝`REPLAY_PY` ＋ 下面這段）：
   ```python
   import subprocess, sys
   from migration.migration_linter import lint
   history = load_history()
   after = prepare_history(history, "claude-fable-5", "claude-opus-4-8")

   def body(msgs):
       return {"model": "claude-opus-4-8", "output_config": {"effort": "medium"}, "messages": msgs}

   for name, msgs, fname in [("處理前", history, "request-before.json"), ("處理後", after, "request-after.json")]:
       req = body(msgs)
       (WORK / fname).write_text(json.dumps(req, ensure_ascii=False, indent=2), encoding="utf-8")
       findings = lint(req)
       has_msg = any(f == "messages" for f, _, _ in findings)
       print(name + "：" + str(len(findings)) + " 個發現｜messages 警告：" + ("有" if has_msg else "無 ✅"))
       for f, sev, msg in findings:
           print("    " + sev + "  " + f + "｜" + msg[:60])
   print()
   print("──── 用 linter 命令列跑處理後的檔案 ────")
   r = subprocess.run([sys.executable, "migration/migration_linter.py", str(WORK / "request-after.json")],
                      capture_output=True, text=True, encoding="utf-8")
   print("  " + r.stdout.strip())
   print()
   print("──── 唯一的例外：fallback_credit/credit_retry.py 第 36～37 行 ────")
   for line in Path("fallback_credit/credit_retry.py").read_text(encoding="utf-8").splitlines()[35:37]:
       print("  " + line)
   ```

   - `處理前：1 個發現｜messages 警告：有`，下面一行是 `warn  messages｜Assistant turn carries a thinking block...`。

     - 因為 model 是 opus，不會觸發 `fallbacks` 警告；也有 effort，不會觸發 info。

## 第 7 步：真的交給「備援模型」接手（呼叫模型 1 次）

1. **標題**：剝完思考的歷史，接手的模型還接得下去嗎
2. **目的**：確認剝掉思考區塊不會丟掉對話裡真正的資訊：工具查到的 IP 還在 tool_result 裡，接手的模型照樣答得出來。同時照實說明轉接層的限制：`claude_cli_client` 攤平對話時本來就不送 thinking 區塊（第 98 行），所以在本機重現不了「同模型刪空 thinking → 400」，那一條只能靠第 3、5 步的位元組比對來守。
3. **指令**（py_run，程式＝`REPLAY_PY` ＋ 下面這段；約需 20～90 秒）：
   ```python
   import os
   import anthropic
   log = WORK / "calls.jsonl"
   if log.exists():
   ```
