## 第 1 步：調度停擺 20 分鐘：機器人自己重分配

**目的**：用開場故事讓學習者看見「沒有人下指令，系統也能自己走路」：包裹堆在少數幾台機器人身上，等中央派工的話，閒著的機器人只能乾等；只要加上一條本地規則「閒的去拉最忙鄰居的工作」，負載平衡就自己長出來，準時把包裹出完。

**tip 建議**：倉庫 23 台機器人、300 件包裹，約 7 成堆在靠近出貨口的 5 台身上。中央調度系統當機不發指令。左邊：每台只做自己佇列裡的；右邊：每台每步看隨機 4 個鄰居，自己的佇列比鄰居平均少 3 成以上，就從最忙的鄰居拉 1 件。每步 = 15 秒，出貨窗口是第 24 步（6 分鐘）。

**要跑的內嵌 Python**：

```python
import random

random.seed(144)
R, P, HOT, OK, DEADLINE = 23, 300, 5, 0.95, 24

def initial():
    q = [0] * R
    for _ in range(P):
        if random.random() < 0.7:
            q[random.randrange(HOT)] += 1
        else:
            q[random.randrange(HOT, R)] += 1
    return q

START = initial()

def simulate(local):
    q = list(START)
    done, t, idle, pulls = 0, 0, 0, 0
    curve = {}
    while done < P and t < 200:
        t += 1
        if local:
            for i in range(R):
                nb = random.sample([j for j in range(R) if j != i], 4)
                avg = sum(q[j] for j in nb) / 4
                busiest = max(nb, key=lambda j: q[j])
                if q[i] < 0.7 * avg and q[busiest] > q[i] + 1:
                    q[busiest] -= 1
                    q[i] += 1
                    pulls += 1
        for i in range(R):
            if q[i] == 0:
                idle += 1
            elif random.random() < OK:
                q[i] -= 1
                done += 1
        curve[t] = done
    return t, curve, idle, pulls

hot = START[:HOT]
rest = START[HOT:]
print(f"倉庫：{R} 台機器人、{P} 件包裹；中央調度系統 20 分鐘沒發指令（每步 = 15 秒）")
print(f"包裹約 7 成堆在靠近出貨口的 {HOT} 台身上：{hot}；其餘 {R - HOT} 台平均 {sum(rest) / len(rest):.1f} 件")
print(f"出貨窗口：第 {DEADLINE} 步（6 分鐘）前要出完")
print()
rows = (("等中央派工：各做各的", False), ("三條本地規則：閒的主動去拉", True))
print(" 做法                       | 第6步 | 第12步 | 第18步 | 第24步 | 全部出完 | 閒置台·步 | 拉取次數")
print("-" * 92)
result = {}
for name, local in rows:
    t, curve, idle, pulls = simulate(local)
    cells = [curve.get(s, P) for s in (6, 12, 18, 24)]
    result[local] = cells[3]
    print(f" {name:<22} | {cells[0]:>5} | {cells[1]:>6} | {cells[2]:>6} | {cells[3]:>6} | 第 {t:>3} 步 | {idle:>9} | {pulls:>8}")
print()
miss = P - result[False]
print(f"等中央派工：窗口前只出了 {result[False]} 件，{miss} 件錯過出貨；本地規則：出了 {result[True]} 件。")
print("沒有任何一條規則寫「要變高效」——只是「閒的去拉最忙鄰居的工作」，負載平衡就自己長出來了。")
```

**預期看到什麼**：
- 開頭：熱區 5 台的佇列是 5 個數字，各約 42（30～55）；其餘 18 台平均約 5 件（3.5～6.5）。
- 表格兩列，欄位：做法｜第6步｜第12步｜第18步｜第24步｜全部出完｜閒置台·步｜拉取次數（各步欄位是「累積出貨件數」）。
  - 等中央派工：第 6 步約 105（90～120）、第 12 步約 145（130～160）、第 18 步約 175（160～190）、第 24 步約 204（185～225）；全部出完在第 **約 52 步**（42～65）；閒置台·步約 800（650～1,000）；拉取次數 **0**。
  - 本地規則：第 6 步約 120（105～135）、第 12 步約 240（220～265）、第 18 步接近或等於 300、第 24 步 **300**；全部出完在第 **14～20 步**；閒置台·步很少（< 100）；拉取次數約 130～250。
- 結尾：「窗口前只出了 約 204 件，約 96 件錯過出貨；本地規則：出了 300 件。」以及「沒有任何一條規則寫要變高效」那一行。

**是否呼叫模型**：否

## 第 2 步：規則 a：重複度門檻為什麼是 80% 左右

**目的**：第一條本地規則「相似度超過約 80% 的任務合併給同一節點」不是隨便訂的數字。讓學習者掃描門檻，看見它是「省工時」與「誤合併返工」之間的權衡：門檻太低會把長得像但不同的任務合在一起，太高則錯過該合併的。

**tip 建議**：3,000 對任務兩兩比對：900 對其實是同一種任務（相似度 0.72～1.0），600 對是同類但不同任務（0.45～0.82，最容易誤判），1,500 對無關（0～0.45）。正確合併省 1 單位工時，誤合併要返工賠 3 單位。

**要跑的內嵌 Python**：

```python
import random

random.seed(144)
PAIRS = [("同一種任務", 900), ("同類但不同任務", 600), ("無關任務", 1500)]
RANGE = {"同一種任務": (0.72, 1.0), "同類但不同任務": (0.45, 0.82), "無關任務": (0.0, 0.45)}
SAVE, REWORK = 1.0, 3.0
pairs = []
for kind, n in PAIRS:
    lo, hi = RANGE[kind]
    for _ in range(n):
        pairs.append((kind, random.uniform(lo, hi)))

print(f"{len(pairs):,} 對任務兩兩比對；相似度 ≥ 門檻就合併給同一節點")
for kind, n in PAIRS:
    vals = [s for k, s in pairs if k == kind]
    print(f"  {kind:<8}：{n:>5} 對，平均相似度 {sum(vals) / n:.2f}（最低 {min(vals):.2f}、最高 {max(vals):.2f}）")
print(f"正確合併（同一種任務）省 {SAVE:g} 單位工時；誤合併（其實不同）要返工，賠 {REWORK:g} 單位")
print()
print(" 門檻 | 合併數 | 正確合併 | 誤合併 | 漏合併 | 淨效益")
print("-" * 54)
table = []
for t in (0.60, 0.65, 0.70, 0.75, 0.80, 0.85, 0.90, 0.95):
    good = sum(1 for k, s in pairs if s >= t and k == "同一種任務")
    bad = sum(1 for k, s in pairs if s >= t and k != "同一種任務")
    miss = 900 - good
    net = SAVE * good - REWORK * bad
    table.append((t, good + bad, good, bad, miss, net))
best = max(table, key=lambda r: r[5])
for t, m, good, bad, miss, net in table:
    mark = " ←最佳" if t == best[0] else ""
    print(f" {t:.2f} | {m:>6} | {good:>8} | {bad:>6} | {miss:>6} | {net:>7.0f}{mark}")
print()
print(f"淨效益最高的門檻是 {best[0]:.2f}。門檻太低：把「長得像但不同」的任務誤合併，返工吃掉省下的時間；")
print("門檻太高：該合併的沒合併。書中「相似度約 80%」就是這個權衡的經驗值——要依返工成本調，不是常數。")
```

**預期看到什麼**：
- 三行平均相似度：同一種任務約 0.86、同類但不同任務約 0.64、無關任務約 0.23（各 ±0.02）；最低／最高大致貼著 0.72／1.00、0.45／0.82、0.00／0.45。
- 門檻表 8 列，欄位：門檻｜合併數｜正確合併｜誤合併｜漏合併｜淨效益。大致數值（±30 件、淨效益 ±60）：
  - 0.60：正確 900、誤合併約 357、漏合併 0、淨效益約 −170（負的）
  - 0.65：正確 900、誤合併約 276、淨效益約 +73
  - 0.70：正確 900、誤合併約 195、淨效益約 316
  - 0.75：正確約 804、誤合併約 114、淨效益約 463
  - **0.80：正確約 643、誤合併約 32、淨效益約 546 ←最佳**
  - 0.85：正確約 482、誤合併 **0**、淨效益約 482
  - 0.90：正確約 321、誤合併 0、淨效益約 321
  - 0.95：正確約 161、誤合併 0、淨效益約 161
- 「正確合併」隨門檻上升而遞減、「誤合併」遞減到 0、「漏合併」遞增；「←最佳」標在 **0.80** 那一列。
- 結尾「淨效益最高的門檻是 0.80」。

**是否呼叫模型**：否

## 第 3 步：規則 b＋c：負載梯度、懲罰冷卻，與「偷看全域」的陷阱

**目的**：把第二、三條規則拆開來看：負載梯度（閒的去拉）解決任務塞在入口；懲罰冷卻（連續失敗 3 次休息 5 步）讓劣化節點不再一直接單、一直失敗。最後一列是陷阱：如果讓每個節點偷看全部節點，效果差不多，但資訊量暴增——規則一旦依賴全域資訊，就又退回中央排程。

**tip 建議**：30 個節點、200 步，每步 22 件任務，一半從 5 個入口節點進來。第 50 步起節點 10～13 劣化，成功率從 95% 掉到 20%。四種設定共用同一串亂數，只差規則。

**要跑的內嵌 Python**：

```python
import random

random.seed(144)
N, STEPS, OK, BAD_OK, BAD_FROM = 30, 200, 0.95, 0.2, 50
HOT = list(range(5))
BAD = {10, 11, 12, 13}

def build_world():
    rng = random.Random(3030)
    arrivals = []
    for t in range(STEPS):
        arrivals.append([rng.choice(HOT) if rng.random() < 0.5 else rng.randrange(5, N) for _ in range(22)])
    draws = [[rng.random() for _ in range(N)] for _ in range(STEPS)]
    nbrs = [[[j + (j >= i) for j in rng.sample(range(N - 1), 4)] for i in range(N)] for _ in range(STEPS)]
    return arrivals, draws, nbrs

ARR, DRAWS, NBRS = build_world()

def run(pull, penalty, global_view=False):
    q = [0] * N
    fails = [0] * N
    cool = [0] * N
    done = wasted = moved = reads = 0
    for t in range(STEPS):
        for node in ARR[t]:
            if cool[node] > 0:
                node = NBRS[t][node][0]          # 冷卻中不接單：轉給鄰居
            q[node] += 1
        if pull:
            for i in range(N):
                if cool[i] > 0:
                    continue
                nb = [j for j in range(N) if j != i] if global_view else NBRS[t][i]
                reads += len(nb)
                avg = sum(q[j] for j in nb) / len(nb)
                busiest = max(nb, key=lambda j: q[j])
                if q[i] < 0.7 * avg and q[busiest] > q[i] + 1:
                    q[busiest] -= 1
                    q[i] += 1
                    moved += 1
        for i in range(N):
            if cool[i] > 0:
                cool[i] -= 1
                continue
            if q[i] == 0:
                continue
            p = BAD_OK if (i in BAD and t >= BAD_FROM) else OK
            if DRAWS[t][i] < p:
                q[i] -= 1
                done += 1
                fails[i] = 0
            else:
                wasted += 1
                fails[i] += 1
                if penalty and fails[i] >= 3:
                    cool[i] = 5
                    fails[i] = 0
    arrived = sum(len(b) for b in ARR)
    return done, arrived, sum(q), max(q), wasted, moved, reads / STEPS

print(f"{N} 個節點、{STEPS} 步；每步 22 件任務，一半從 5 個入口節點進來；第 {BAD_FROM} 步起節點 10～13 劣化（成功率 95% → 20%）")
print("b 負載梯度：自己的佇列 < 鄰居平均 × 0.7，就從最忙的鄰居拉 1 件；c 懲罰：連續失敗 3 次 → 冷卻 5 步，不接單")
print()
print(" 設定                         | 完成數 | 完成率 | 最終積壓 | 結束時最長佇列 | 失敗嘗試 | 搬運次數 | 每步讀取節點數")
print("-" * 110)
configs = [("沒有規則：任務留在進貨節點", False, False, False), ("只開 b 負載梯度", True, False, False),
           ("b ＋ c 懲罰冷卻", True, True, False), ("b ＋ c，但改看全域資訊", True, True, True)]
out = {}
for name, pull, pen, gv in configs:
    r = run(pull, pen, gv)
    out[name] = r
    done, arrived, left, peak, wasted, moved, reads = r
    print(f" {name:<24} | {done:>6,} | {done / arrived:>6.1%} | {left:>8,} | {peak:>14} | {wasted:>8} | {moved:>8,} | {reads:>14.0f}")
print()
w_b = out["只開 b 負載梯度"][4]
w_bc = out["b ＋ c 懲罰冷卻"][4]
r_l = out["b ＋ c 懲罰冷卻"][6]
r_g = out["b ＋ c，但改看全域資訊"][6]
print(f"懲罰冷卻讓失敗嘗試從 {w_b} 降到 {w_bc}（少 {1 - w_bc / w_b:.0%}）：劣化節點不再一直接單、一直失敗。")
print(f"改看全域資訊，完成率差不多，但每步要讀 {r_g:.0f} 筆節點資訊，是本地的 {r_g / r_l:.1f} 倍——規則一旦依賴全域資訊，就又退回中央排程。")
```

**預期看到什麼**：
- 表格 4 列，欄位：設定｜完成數｜完成率｜最終積壓｜結束時最長佇列｜失敗嘗試｜搬運次數｜每步讀取節點數。到達總數固定 4,400。
  - 沒有規則：完成約 3,000（2,850～3,150），完成率約 68%（64～72%）；最終積壓約 1,400（1,250～1,550）；結束時最長佇列約 270（230～310，是入口節點）；失敗嘗試約 630（570～700）；搬運 **0**；每步讀取 **0**。
  - 只開 b：完成率 **≥ 97%**（通常 98～99.9%）；最終積壓幾十件以內；結束時最長佇列 < 20；失敗嘗試約 690（600～770）；搬運 1,300 次以上；每步讀取 **120**。
  - b＋c：完成率同樣 ≥ 97%；失敗嘗試**明顯少於只開 b**（約 380～490）；每步讀取約 118～120。
  - b＋c 看全域：完成率 ≥ 97%；每步讀取約 **860～870**。
- 結尾第一行：「失敗嘗試從 約 690 降到 約 430（少 25%～45%）」。
- 結尾第二行：全域讀取量是本地的 **約 7.2～7.4 倍**，並有「退回中央排程」字樣。

**是否呼叫模型**：否

## 第 4 步：練習 1：中央排程 vs 三條本地規則（η、T90、敏感度）

**目的**：做練習 1 的完整實驗。看宏觀指標而不是單一代理：中央排程受派工上限（每步 40 件）與延遲拖累，規模越大 η 越低；三條本地規則的 η 很穩。故障衝擊下，中央排程停擺在曲線上留下明顯缺口、T90 十幾步，本地規則幾步內就回來。最後用「只差 1 件任務」的兩次跑法，看系統會不會把小差異放大（Lyapunov 的直覺）。也照實檢查書中「約 120 個節點出現拐點」在這個模擬裡有沒有出現。

**tip 建議**：N = 20、60、120、200，每種跑 300 步。每步到達 Poisson(0.4N) 件、20 種類型，60% 從 20% 的入口節點進來。central：每步最多派 40 件、每 50 個節點多延遲 1 步。local：三條本地規則（同類合併、負載梯度、懲罰冷卻），每個節點只看隨機 4 個鄰居。第 150 步 15% 節點故障 30 步，central 的排程器另外停擺 10 步。結果寫到 ch04/interactive/self_org_warehouse.csv。

**要跑的內嵌 Python**：

```python
import csv
import math
import os
import random

def poisson(rng, lam):
    limit, k, p = math.exp(-lam), 0, 1.0
    while True:
        p *= rng.random()
        if p <= limit:
            return k
        k += 1

def make_world(n):
    rng = random.Random(1440 + n)
    entries = rng.sample(range(n), n // 5)
    failed = set(rng.sample(range(n), round(n * 0.15)))
    arrivals = []
    for t in range(STEPS):
        batch = []
        for _ in range(poisson(rng, 0.4 * n)):
            node = rng.choice(entries) if rng.random() < 0.6 else rng.randrange(n)
            batch.append((rng.randrange(TYPES), node))
        arrivals.append(batch)
    act = random.Random(2880 + n)
    draws = [[act.random() for _ in range(n)] for _ in range(STEPS)]
    nbrs = [[[j + (j >= i) for j in act.sample(range(n - 1), 4)] for i in range(n)] for _ in range(STEPS)]
    return failed, arrivals, draws, nbrs

def run_local(n, world, extra=0):
    failed, arrivals, draws, nbrs = world
    q = [[i % TYPES] for i in range(n)]
    for _ in range(extra):
        q[0].append(TYPES - 1)
    fails, cool = [0] * n, [0] * n
    done = [0] * STEPS
    arrived = n + extra
    longest = 0
    snaps = {}
    for t in range(STEPS):
        down = failed if FAIL_AT <= t < FAIL_AT + FAIL_LEN else set()
        for typ, node in arrivals[t]:
            if cool[node] > 0:
                node = nbrs[t][node][0]
            q[node].append(typ)
        arrived += len(arrivals[t])
        for i in range(n):                                  # 規則 b：負載梯度
            if i in down or cool[i] > 0:
                continue
            nb = nbrs[t][i]
            avg = sum(len(q[j]) for j in nb) / 4
            busiest = max(nb, key=lambda j: len(q[j]))
            if len(q[i]) < 0.7 * avg and len(q[busiest]) > len(q[i]) + 1:
                q[i].append(q[busiest].pop())
        for i in range(n):
            if cool[i] > 0:
                cool[i] -= 1
                continue
            if i in down or not q[i]:
                continue
            if draws[t][i] < OK:
                typ = q[i].pop(0)
                done[t] += 1
                fails[i] = 0
                if typ in q[i]:                             # 規則 a：同類型合併，第二件耗時減半
                    q[i].remove(typ)
                    done[t] += 1
            else:
                fails[i] += 1
                if fails[i] >= 3:                           # 規則 c：連續失敗 3 次，冷卻 5 步
                    cool[i] = 5
                    fails[i] = 0
        longest = max(longest, max(len(x) for x in q))
        snaps[t] = [len(x) for x in q]
    return done, arrived, longest, snaps

def run_central(n, world):
    failed, arrivals, draws, nbrs = world
    delay = n // 50
    backlog = n
    nodeq = [0] * n
    pending = []
    done = [0] * STEPS
    arrived = n
    longest = 0
    for t in range(STEPS):
        down = failed if FAIL_AT <= t < FAIL_AT + FAIL_LEN else set()
        backlog += len(arrivals[t])
        arrived += len(arrivals[t])
        if not (FAIL_AT <= t < FAIL_AT + STALL):           # 排程器在第 150 步停擺 10 步
            k = min(C_MAX, backlog)
            backlog -= k
            alive = sorted((i for i in range(n) if i not in down), key=lambda i: nodeq[i])
            for m in range(k):
                pending.append((t + delay, alive[m % len(alive)]))
        keep = []
        for due, node in pending:
            if due <= t:
                nodeq[node] += 1
            else:
                keep.append((due, node))
        pending = keep
        for i in range(n):
            if i in down or nodeq[i] == 0:
                continue
            if draws[t][i] < OK:
                nodeq[i] -= 1
                done[t] += 1
        longest = max(longest, backlog)
    return done, arrived, longest

def t90(done):
    base = sum(done[FAIL_AT - 50:FAIL_AT]) / 50
    roll = []
    for t in range(STEPS):
        w = done[max(0, t - 4):t + 1]
        roll.append(sum(w) / len(w))
    dip = next((t for t in range(FAIL_AT, STEPS) if roll[t] < 0.9 * base), None)
    if dip is None:
        return 0
    back = next((t for t in range(dip + 1, STEPS) if roll[t] >= 0.9 * base), None)
    return None if back is None else back - FAIL_AT
```

## 第 5 步：反饋延遲與吸引子：湧現不是永遠都會發生

**目的**：書中說規則要能湧現，反饋延遲必須在可接受範圍內；而且湧現的系統會被「吸引子」拉走。前半段讓節點用「d 步以前的鄰居資訊」推送工作，看延遲越大越會一窩蜂推給「看起來很閒、其實早就滿了」的節點，搬運與失衡都變多。後半段：同樣的規則、同樣的負載，只是起點不同（空倉 vs 已經塞車），就會落到「高效」或「擁堵」兩個不同的吸引子——治理要做的，是把系統留在對的盆地裡。

**tip 建議**：前半：40 個節點，每步 30 件任務全從 4 個入口進來（總處理能力約 36），每個節點把「自己佇列 − 看到的鄰居佇列」的一半推給看起來最閒的鄰居，但看到的是 d 步以前的數字。後半：佇列超過 8 件就會塞車，處理成功率從 95% 掉到 60%；負載 ρ = 0.4、0.7、0.9，各從空倉與每個節點 30 件開始跑 300 步。

```python
import random

random.seed(144)
N = 40

def run_delay(d, steps=200, arrive=30, entry=4, ok=0.9):
    rng = random.Random(4040)
    q = [0] * N
    hist = []
    moved = peak = 0
    imbal = 0.0
    for t in range(steps):
        for _ in range(arrive):
            q[rng.randrange(entry)] += 1
        hist.append(list(q))
        view = hist[max(0, len(hist) - 1 - d)]          # 看到的是 d 步以前的鄰居佇列
        for i in rng.sample(range(N), N):
            nb = [j + (j >= i) for j in rng.sample(range(N - 1), 4)]
            light = min(nb, key=lambda j: view[j])
            gap = q[i] - view[light]
            if gap >= 2:
                k = gap // 2
                q[i] -= k
                q[light] += k
                moved += k
        for i in range(N):
            if q[i] > 0 and rng.random() < ok:
                q[i] -= 1
        peak = max(peak, max(q))
        if t >= 50:
            m = sum(q) / N
            imbal += (sum((x - m) ** 2 for x in q) / N) ** 0.5
    return moved, peak, imbal / (steps - 50), sum(q)

def run_attractor(rho, start, steps=300):
    rng = random.Random(5050)
    q = [start] * N
    tail = []
    for t in range(steps):
        for i in range(N):
            if rng.random() < rho:
                q[i] += 1
        for i in range(N):
            nb = [j + (j >= i) for j in rng.sample(range(N - 1), 4)]
            b = max(nb, key=lambda j: q[j])
            if q[b] > q[i] + 1:
                q[b] -= 1
                q[i] += 1
        for i in range(N):
            cap = 0.95 if q[i] <= 8 else 0.6             # 佇列太長：通道互卡，效率掉到 6 成
            if q[i] > 0 and rng.random() < cap:
                q[i] -= 1
        if t >= steps - 50:
            tail.append(sum(q) / N)
    return sum(tail) / len(tail)
```

## 第 6 步：練習 2A：內容工廠的資訊級聯（三種策略）

**目的**：物流倉庫有物理剎車（不能穿牆、不能同占一格），內容工廠沒有。讓學習者看見：一千個寫作代理只看本地熱度訊號時會一窩蜂寫同一題（資訊級聯）；加上本地剎車（鄰居已有 3 人寫就降權）能減輕；再加上中央只設邊界（每題全域配額 60 篇）的混合架構，任何話題都被壓在上限以內。這一步也把「第 10 輪結束時某個代理看得到的本地視角」存起來，給第 7 步交給真實模型。

**tip 建議**：500 個寫作代理、12 個話題，排成一圈，每人只看左右各 3 位。20 輪、每輪 25 人決定寫什麼。權重 =（鄰居中寫該話題人數 + 1）×（平台累積篇數 + 1）^1.5。每個話題每輪審稿台只收 4 篇，多的退稿——用來看負載震盪。三種策略共用同一個決策順序與同一串亂數。結果寫到 ch04/interactive/herding_state.json。

```python
                x = (c + 1) * (counts[k] + 1) ** 1.5           # 跟風：鄰居在寫＋平台熱度
                if strategy != "follow" and c >= 3:
                    x *= 0.1                                    # 本地剎車：鄰居已有 3 人寫
                if strategy == "hybrid" and counts[k] >= QUOTA:
                    x = 0.0                                     # 中央邊界：全域配額 60 篇
                w.append(x)
            k = rng.choices(range(K), weights=w)[0]
            choice[i] = k
            counts[k] += 1
            desk[k] += 1
            if desk[k] <= DESK:
                ok += 1
        accepted.append(ok)
        if r == 9:
            snap = {"choice": list(choice), "counts": list(counts), "next": order[10 * PER:11 * PER]}
    return counts, accepted, snap

def metrics(counts, accepted):
    top = max(counts) / A
    dup = sum(max(0, c - OVER) for c in counts) / A
    mean = sum(accepted) / len(accepted)
    sd = (sum((a - mean) ** 2 for a in accepted) / len(accepted)) ** 0.5
    return top, dup, mean, sd / mean

results = {}
print(f"{A} 個寫作代理、{K} 個話題；環狀排列，每人只看左右各 3 位；{ROUNDS} 輪 × 每輪 {PER} 人決定寫什麼")

for s in STRATS:

print("  鄰居中最多人寫：" + (nb_top if nb_top else "（鄰居都還沒寫）"))
print("  平台熱度前 5：" + "；".join(h[0] + " " + str(h[1]) + " 篇" for h in heat))
print("  hybrid 在同一時間點已額滿的話題：" + ("、".join(full) if full else "（還沒有）"))

state = {"topics": TOPICS, "quota": QUOTA,
         "metrics": {s: {"max_share": results[s]["max_share"], "dup_rate": results[s]["dup_rate"],
                         "accept_mean": results[s]["accept_mean"], "cv": results[s]["cv"]} for s in STRATS},
         "final_counts": {s: results[s]["counts"] for s in STRATS},
         "agent": agent, "neighbors_view": nb_view, "neighbors_top": nb_top, "heat_top5": heat,
         "hybrid_round10_counts": hyb}
```
