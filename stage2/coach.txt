長時程多代理　階段 2：動手蓋（對照 K138）教練稿

【2-0：環境檢查】
第二階段，動手蓋。這個階段要自己寫出主持人加子代理的程式，能平行、能共享檔案、能中斷後接續，觀念對照 K138，實作改用 Claude Code 子代理和 claude 杠 p。第一步 2-0，環境檢查，只查三件事：claude 指令可用；沒有設 ANTHROPIC API KEY，設了會改扣 API 費用；無頭模式 claude 杠 p 有回應。不檢查顯卡、不跑本機模型。

【2-1：第一個長任務代理】
步驟 2-1，第一個長任務代理，對照 K138 第五到八章。我們用 claude 杠 p 交一個任務：整理三個 ROS 2 學習重點，先列待辦，再寫成 notes.md。只開放兩個工具：待辦清單和寫檔。看三件事：一，它是不是先列待辦再動手，這是防止跑偏的第一招；二，內容是寫進檔案，而不是全塞在對話裡；三，最後的結果裡有 session_id、輪數和成本，之後中斷接續就靠 session_id。

【2-2：平行子代理】
步驟 2-2，平行子代理，對照 K138 第十章。我們在練習資料夾定義兩個子代理：優點研究員和缺點研究員，各自一個 md 檔，標頭寫名字、說明和可用工具，內文是角色提示詞。主持人只開放一個工具：派子代理，這次用 tools 參數真的限制住。題目是：在家用電腦連續二十四小時跑多代理程式。看重點：兩個子代理是不是在同一則訊息裡一起派出去，也就是真的平行；最後主持人合成五行結論。

【2-2b：平行子代理（修正後重跑）】
重跑 2-2。剛才兩個子代理被拒絕啟動，因為它們要用讀檔工具，但主持人這一場只開放派子代理一種工具，子代理拿不到任何工具。另外，全域設定裡的 hook 逼主持人去提交程式，結論被蓋掉了。修正：開放派子代理和讀檔兩種工具，並且只載入專案設定，不載入使用者層級的 hook。

【2-3：研究團隊】
步驟 2-3，研究團隊，對照 K138 第十一章。主持人把題目拆成兩個子題，同時派兩位研究員上網查資料，各寫一份筆記檔。關鍵規則：研究員回報給主持人時，只寫兩句結論加檔名，詳細內容放檔案。這叫訊息隔離和成果共享：主持人的上下文不會被大量資料塞滿，需要時再讀檔。最後主持人讀回兩份筆記，寫總報告。題目是：Claude Code 的子代理和無頭模式各適合什麼情境。

【2-4a：中斷與接續（第 1 段：跑到一半按 Ctrl+C）】
步驟 2-4，中斷與接續，這是長時程的核心，對照 K138 第七、十八、二十章。run_task.py 把任務分四個階段：拆子題、逐一寫筆記、合成報告、寄出前等核准。每做完一小步，就把進度寫進 state.json，這就是 K138 的檢查點。現在第一段示範：真的用 claude 杠 p 從頭跑，等第一個子題寫完，我就按 Ctrl C 強制中斷。

【2-4b：中斷與接續（第 2 段：重跑接續）】
第二段，什麼都不改，再執行一次 run_task.py。程式會先讀 state.json，知道自己停在研究階段，而且子題一、二已經完成。預期它會印出跳過這兩個子題，只補做子題三，接著合成報告。報告要寄出是對外動作，所以它會停在待核准，然後結束程式。這對照 K138 的 interrupt on：遇到需要人決定的動作，就停下來交給人。

【2-4c：中斷與接續（第 3 段：核准後寄出）】
第三段，人工核准。你看過報告、同意寄出，就執行 run_task.py 加上 approve。程式確認目前是待核准狀態，才把報告寄出。這次的寄出是模擬的：複製到 outbox 資料夾，開頭加寄出時間，不會真的寄信。核准可以隔很久才下，甚至隔天，因為狀態都在檔案裡，程式不需要一直開著等。

【2-5：分工修程式】
步驟 2-5，分工修程式，對照 K138 第二十一章。專案是一個故意埋了三個 bug 的庫存模組，十個測試有三個失敗。三個角色：分析員只有讀檔和跑指令的工具，負責找 bug、寫修改計畫，不能改檔；修改員有改檔工具，只照計畫修，不能改測試；主持人只協調，不碰檔案。看重點：每個角色實際用了哪些工具，最後測試是否全部通過，以及 git diff 看到改了哪幾行。這就是第三階段意圖合約的雛形。

【2-5b：分工修程式（修正後重跑）】
重跑 2-5。剛才失敗有兩個原因：練習格停在上一步的資料夾，主持人找不到分析員和修改員的定義，只好交給通用代理一個人全包；另外子代理先切換目錄再跑測試，和允許的指令格式對不上，被權限擋下。修正後，在正確的資料夾執行，子代理直接跑 pytest。這次看三個角色是不是各做各的。
