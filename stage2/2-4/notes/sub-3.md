# 子題 3：多代理協調與品質把關：任務分工、錯誤重試、結果驗證與避免代理間互相干擾

- 任務分工要明確切割職責與輸入／輸出邊界，每個代理只寫自己的檔案或工作目錄（如 git worktree），避免共用狀態造成互相覆寫與鎖衝突。
- 錯誤重試採指數退避並設上限次數，搭配冪等設計與檢查點（state 檔），讓失敗步驟可安全重跑、中斷後能從斷點接續而非從頭來。
- 結果驗證不能只信代理自述，要用獨立的 QA／審查代理或自動化測試交叉檢查，產出格式以 schema 驗證，不合格就退回重做。
- 代理之間透過明確的訊息佇列或交接檔溝通，不直接改彼此的中間產物，並記錄每次交接的版本與時間，方便追查是誰引入錯誤。
- 長時間運行要設監控與熔斷機制：偵測重複迴圈、成本或 token 暴衝、代理卡住無進度時自動暫停並告警，避免一個代理失控拖垮整個系統。
