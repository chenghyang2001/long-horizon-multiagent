## 第 1 步：任務網絡的邊有兩個權重：合併、分開還是串接

**目的**：本章主角是「會動態重組的任務網絡」。先讓學習者看見：任務之間的每條邊都有兩個數字——資料依賴度（兩個任務的資料重疊多少）與時間窗（多急）。同一張圖，權重不同做法就不同：依賴高又不急的合併或共用中間結果；依賴低又都很急的分開跑免得搶資源；依賴高但很急的不合併、讓上游先走。開頭用書中「用戶回饋 vs 客戶投訴重疊 34%」的例子算出依賴度。

**tip 建議**：兩個團隊各自整理 500 則問題單（用戶回饋、客戶投訴），系統比對問題單 ID 算出資料依賴度。接著 8 條任務邊各有「資料依賴度」與「時間窗（小時）」：依賴 ≥ 30% 且時間窗 ≥ 24 小時 → MERGE；依賴 < 20% 且時間窗 ≤ 6 小時 → SPLIT；依賴 ≥ 30% 但時間窗 ≤ 6 小時 → CHAIN；其他照原排程。

**要跑的內嵌 Python**：

```python
import random

random.seed(5)
universe = list(range(1, 2001))
feedback = set(random.sample(universe, 500))
others = [x for x in universe if x not in feedback]
complaint = set(random.sample(sorted(feedback), 170)) | set(random.sample(others, 330))
shared = feedback & complaint
dep_fc = len(shared) / len(complaint)
print("兩個團隊各自整理 500 則問題單：A 團隊＝用戶回饋，B 團隊＝客戶投訴")
print(f"系統比對問題單 ID：兩邊共同的有 {len(shared)} 則 → 資料依賴度 = {len(shared)} / {len(complaint)} = {dep_fc:.0%}")
print()

def decide(dep, window):
    if dep >= 0.3 and window >= 24:
        return "MERGE", "依賴高又不急：合併或共用中間結果"
    if dep < 0.2 and window <= 6:
        return "SPLIT", "依賴低又都很急：分開跑，免得搶資源"
    if dep >= 0.3 and window <= 6:
        return "CHAIN", "依賴高但很急：不合併，讓上游先走"
    return "KEEP", "照原排程"

edges = [
    ("用戶回饋整理", "客戶投訴整理", dep_fc, 48),
    ("市場數據清洗", "競品價格表", 0.62, 72),
    ("第 3 章素材", "第 4 章素材", 0.45, 24),
    ("災區道路回報", "物資調度", 0.71, 3),
    ("災區傷患回報", "物資調度", 0.12, 2),
    ("客服日誌彙整", "退款統計", 0.18, 4),
    ("問卷清洗", "問卷分析", 0.55, 12),
    ("週報排版", "月報排版", 0.08, 168),
]
print(" 上游任務     → 下游任務     | 資料依賴度 | 時間窗(小時) | 決定  | 理由")
print("-" * 90)
count = {}
for a, b, dep, win in edges:
    tag, why = decide(dep, win)
    count[tag] = count.get(tag, 0) + 1
    print(f" {a:<10} → {b:<8} | {dep:>10.0%} | {win:>12} | {tag:<5} | {why}")
print()
print("統計：" + "、".join(k + " " + str(v) + " 條" for k, v in sorted(count.items())))
print("同一張圖，換了權重就換了做法：任務不是照開工時畫好的流程圖走，")
print("而是看「跟誰重疊、有多急」自己決定合併、分開還是串接——這就是動態任務網絡。")
```

**預期看到什麼**：
- 第二行**固定**是：「兩邊共同的有 170 則 → 資料依賴度 = 170 / 500 = 34%」（設計上必定是 34%，對應書中例子）。
- 表格 8 列，欄位：上游任務 → 下游任務｜資料依賴度｜時間窗(小時)｜決定｜理由。決定欄**完全固定**：
  - 用戶回饋整理→客戶投訴整理（34%、48）：**MERGE**
  - 市場數據清洗→競品價格表（62%、72）：**MERGE**
  - 第 3 章素材→第 4 章素材（45%、24）：**MERGE**
  - 災區道路回報→物資調度（71%、3）：**CHAIN**
  - 災區傷患回報→物資調度（12%、2）：**SPLIT**
  - 客服日誌彙整→退款統計（18%、4）：**SPLIT**
  - 問卷清洗→問卷分析（55%、12）：**KEEP**
  - 週報排版→月報排版（8%、168）：**KEEP**
- 統計行：「CHAIN 1 條、KEEP 2 條、MERGE 3 條、SPLIT 2 條」。

## 第 2 步：練習 1A：延遲一來，臨界路徑就換人

**目的**：做練習 1 的 A 段。臨界路徑不是開工時算一次就好：延遲落在臨界節點上，總工時剛好加上那段延遲、路徑不變；延遲落在支線上，若沒超過餘裕就被吸收、總工時不變；一旦支線變得比原路徑長，臨界路徑整條換人（CHANGED）。同時用拓撲排序檢查有沒有環，並找出「下游掛最多任務」的瓶頸節點——那是排程該盯緊的地方。

**tip 建議**：12 個任務 T01～T12，工時 2～10 小時隨機（random.seed(5)），16 條依賴邊都是小號指向大號。先故意加一條 T12 → T01 測環檢查。接著跑 10 個 tick（每個 tick 代表每 30 秒重算一次），每個 tick 隨機挑 1 個任務延遲 +1～+4 小時，重算臨界路徑；路徑上的任務組合和上一個 tick 不同就標 CHANGED。結果寫到 ch05/interactive/dag_ticks.json。

**要跑的內嵌 Python**：

```python
import json
import os
import random

random.seed(5)
OUT = "ch05/interactive"
os.makedirs(OUT, exist_ok=True)
NAMES = [f"T{i:02d}" for i in range(1, 13)]
EDGES = [("T01", "T02"), ("T01", "T03"), ("T01", "T04"), ("T02", "T05"), ("T03", "T05"), ("T03", "T06"),
         ("T04", "T07"), ("T05", "T08"), ("T06", "T08"), ("T06", "T09"), ("T07", "T09"), ("T07", "T11"),
         ("T08", "T10"), ("T09", "T11"), ("T10", "T12"), ("T11", "T12")]
hours = {n: random.randint(2, 10) for n in NAMES}
start_hours = dict(hours)

def topo_order(nodes, edges):
    indeg = {n: 0 for n in nodes}
    for a, b in edges:
        indeg[b] += 1
    ready = sorted(n for n in nodes if indeg[n] == 0)
    order = []
    while ready:
        n = ready.pop(0)
        order.append(n)
        for a, b in edges:
            if a == n:
                indeg[b] -= 1
                if indeg[b] == 0:
                    ready.append(b)
                    ready.sort()
    if len(order) != len(nodes):
        stuck = sorted(n for n in nodes if n not in order)
        raise ValueError("任務圖有環，卡住的任務：" + "、".join(stuck))
    return order

def critical_path(hours, edges):
    best, prev = {}, {}
    for n in topo_order(list(hours), edges):
        preds = [a for a, b in edges if b == n]
        if preds:
            p = max(preds, key=lambda a: (best[a], a))
            best[n], prev[n] = best[p] + hours[n], p
        else:
            best[n], prev[n] = hours[n], None
    end = max(best, key=lambda n: (best[n], n))
    path = [end]
    while prev[path[-1]] is not None:
        path.append(prev[path[-1]])
    return path[::-1], best[end]

def downstream(n, edges):
    seen, stack = set(), [n]
    while stack:
        x = stack.pop()
        for a, b in edges:
            if a == x and b not in seen:
                seen.add(b)
                stack.append(b)
    return seen

try:
    topo_order(NAMES, EDGES + [("T12", "T01")])
    print("環檢查：沒有發現環（不應該發生）")
except ValueError as e:
    print("環檢查：故意多加一條 T12 → T01，拓撲排序丟出 ValueError：" + str(e))
print()
print("任務工時（2～10 小時）：" + "  ".join(f"{n}={hours[n]}" for n in NAMES))
path, total = critical_path(hours, EDGES)
start_total = total
start_ps = " → ".join(path)
print(f"開工時的臨界路徑：{start_ps}，總工時 {total} 小時")
print()
print(" tick | 延遲      | 臨界路徑                            | 總工時 | 變化    | 說明")
print("-" * 104)
ticks = []
changed_n = 0
for tick in range(1, 11):
    task = random.choice(NAMES)
    d = random.randint(1, 4)
    on_path = task in path
    hours[task] += d
    new_path, new_total = critical_path(hours, EDGES)
    changed = set(new_path) != set(path)
    if on_path:
        note = f"延遲落在臨界節點上：總工時 +{d}"
    elif changed:
        note = "支線變長超過餘裕：臨界路徑換人"
    else:
        note = "落在支線餘裕內：總工時不變"
    mark = "CHANGED" if changed else "-"
    changed_n += int(changed)
    ps = " → ".join(new_path)
    print(f" {tick:>4} | {task} +{d}h  | {ps:<35} | {new_total:>6} | {mark:<7} | {note}")
    ticks.append({"tick": tick, "task": task, "delay": d, "path": new_path, "total": new_total, "changed": changed})
    path, total = new_path, new_total

down = {n: len(downstream(n, EDGES)) for n in NAMES}
top3 = sorted(NAMES, key=lambda n: (-down[n], n))[:3]
print()
print(f"CHANGED 共 {changed_n} 次 / 10 個 tick；總工時從 {start_total} 小時變成 {total} 小時")
print("瓶頸節點（可到達的下游任務數最多的前 3 名）：" + "、".join(f"{n}（下游 {down[n]} 個）" for n in top3))
print("臨界路徑不是固定的：任何一個節點延遲，最長路徑都可能整條換掉——所以要定期重算，而不是等人來催。")
with open(OUT + "/dag_ticks.json", "w", encoding="utf-8") as f:
    json.dump({"start_hours": start_hours, "final_hours": hours, "edges": EDGES, "start_path": start_ps,
               "start_total": start_total, "ticks": ticks, "changed": changed_n,
               "bottlenecks": [[n, down[n]] for n in top3]}, f, ensure_ascii=False, indent=2)
print("已寫入 " + OUT + "/dag_ticks.json")
```

**預期看到什麼**：
- 第一行：「環檢查：故意多加一條 T12 → T01，拓撲排序丟出 ValueError：任務圖有環，卡住的任務：T01、T02、…、T12」（12 個全卡住，因為整張圖沒有入度 0 的起點）。
- 工時行：12 個 `Txx=數字`，每個數字介於 2～10。
- 開工臨界路徑：以 **T01 開頭、T12 結尾**，5 或 6 個節點；總工時大約 30～50 小時（最少 10、最多 60）。
- 表格 10 列，欄位：tick｜延遲｜臨界路徑｜總工時｜變化｜說明。可以逐列檢查的**必定成立的規則**：
  - 總工時**只升不降**（延遲只會加工時）。
  - 說明是「延遲落在臨界節點上：總工時 +d」的列，總工時**剛好比上一列多 d**，且變化欄是「-」。
  - 說明是「落在支線餘裕內」的列，總工時**和上一列相同**、變化欄是「-」。
  - 變化欄是 CHANGED 的列，延遲的任務一定**不在上一列的臨界路徑上**，且新路徑包含這個任務。
- CHANGED 次數：預期 **至少 1 次**（多半 1～5 次）；若 0 次，記錄下來回報（亂數剛好都落在餘裕內，並非程式錯）。最終總工時 = 開工總工時 + 0～40。
- 瓶頸行**完全固定**：「T01（下游 11 個）、T03（下游 7 個）、T06（下游 5 個）」。
- 最後「已寫入 ch05/interactive/dag_ticks.json」。

**是否呼叫模型**：否

## 第 3 步：每 30 秒增量重算，與回路的總延遲

**目的**：書中說排程要「時間驅動」重算（約每 30 秒一次），而且用增量計算只更新變動處。這一步先證明：增量重算（只從延遲的節點往下傳，下游值沒變就停）和全量重算結果完全一樣，但碰到的節點少很多；越靠上游的延遲牽動越多下游。接著算兩筆「延遲帳」：每 30 秒自動重算 vs 每 2 小時等人來看，發現路徑換人的平均時間差多少；以及回路每多一層就多一段延遲——五個環節各遲兩小時就是十小時。

**tip 建議**：前半用第 2 步同一張 12 任務圖、同一串延遲（random.seed(5)，亂數呼叫順序完全相同），再換成 300 個任務、200 次延遲的大圖。比較「增量重算碰到幾個節點」與「全量重算 = 每次全部重算」，並逐次核對兩者結果一致。後半：1,000 個隨機發生的「路徑換人」事件，看兩種檢查頻率的平均發現延遲；最後算三種回路設計的總延遲。

**要跑的內嵌 Python**：

```python
import random

random.seed(5)
NAMES = [f"T{i:02d}" for i in range(1, 13)]
EDGES = [("T01", "T02"), ("T01", "T03"), ("T01", "T04"), ("T02", "T05"), ("T03", "T05"), ("T03", "T06"),
         ("T04", "T07"), ("T05", "T08"), ("T06", "T08"), ("T06", "T09"), ("T07", "T09"), ("T07", "T11"),
         ("T08", "T10"), ("T09", "T11"), ("T10", "T12"), ("T11", "T12")]
hours = {n: random.randint(2, 10) for n in NAMES}
PRED = {n: [a for a, b in EDGES if b == n] for n in NAMES}
SUCC = {n: [b for a, b in EDGES if a == n] for n in NAMES}

def full(hours, order, pred):
    best = {}
    for n in order:
        best[n] = hours[n] + max((best[p] for p in pred[n]), default=0)
    return best

def incremental(best, hours, order, pred, succ, start):
    dirty = {start}
    touched = 0
    for n in order:                      # 依拓撲序往下傳
        if n not in dirty:
            continue
        touched += 1
        new = hours[n] + max((best[p] for p in pred[n]), default=0)
        if new != best[n]:               # 值有變才通知下游；沒變就停在這裡
            best[n] = new
            dirty.update(succ[n])
    return touched

print("【小圖】第 2 步同一張 12 任務圖、同一串延遲")
print(" tick | 延遲      | 增量重算碰到的節點 | 全量重算的節點 | 結果一致")
print("-" * 72)
best = full(hours, NAMES, PRED)
inc_small = 0
for tick in range(1, 11):
    task = random.choice(NAMES)
    d = random.randint(1, 4)
    hours[task] += d
    t = incremental(best, hours, NAMES, PRED, SUCC, task)
    ok_s = "是" if best == full(hours, NAMES, PRED) else "否"
    inc_small += t
    print(f" {tick:>4} | {task} +{d}h  | {t:>18} | {len(NAMES):>14} | {ok_s}")
print(f"合計：增量 {inc_small} 個節點 vs 全量 {10 * len(NAMES)} 個節點")
print()

rng = random.Random(505)
N, TICKS = 300, 200
H = [rng.randint(2, 10) for _ in range(N)]
PL = [[] for _ in range(N)]
for i in range(1, N):
    k = min(i, rng.randint(1, 3))
    PL[i] = rng.sample(range(max(0, i - 30), i), k)
SL = [[] for _ in range(N)]
for i in range(N):
    for p in PL[i]:
        SL[p].append(i)
ORDER = list(range(N))
best = full(H, ORDER, PL)
inc_big, same = 0, 0
zones = {"前段（任務 0～99）": [], "中段（任務 100～199）": [], "後段（任務 200～299）": []}
labels = list(zones)
for _ in range(TICKS):
    x = rng.randrange(N)
    d = rng.randint(1, 4)
```

## 第 4 步：練習 1B-1：SimHash 指紋粗篩（漢明距 ≤ 3）

```python
    v = [0] * 64

    return out
```

## 第 5 步：練習 1B-2：15% 合併門檻：值不值得合併

**目的**：熵減的第二段：指紋說「像」，不代表就該合併。合併本身要花工時、有出錯風險，只有省下的夠多才划算。用練習 1 的收益公式算 10 組候選任務，比較 15% 與 10% 門檻的合併數，並拆解 15% 從哪裡來（合併耗時 5～8%＋風險約 5%＋安全邊際 2～3%）。最後加一個「如果重疊比例被高估 0.25」的壓力測試：門檻放低，總淨省可能多一點，但開始出現賠錢的合併——15% 用一點收益換「不做虧本合併」。把第 2 步、第 4 步與本步結果整理成 task_dag_report.md。

## 第 6 步：練習 2（離線）：只回「收到」不夠，Monitor 抽檢

**目的**：協作回路分三階。微觀的確認訊息把「以為對方知道」變成「確定對方收到」，但只保證「有溝通」，不保證內容對——200 筆交接全回了「收到」，靠確認訊息抓到的錯是 0。中觀的 Monitor 抽檢補上這個洞：抽得越多抓到越多，估計錯誤率都落在真值附近，但抽太少時估計值跳動很大。最後模擬「某團隊失敗率高就把抽檢率提高到 50%」的規則，看漏到下游的錯少多少。

**tip 建議**：random.seed(55)，200 筆假交接，每筆 8% 機率內容錯誤。抽檢率 10%（20 筆）與 30%（60 筆）各抽一次，再各重抽 1,000 次看估計值的跳動。後半：4 個團隊（真實錯誤率 3%、5%、8%、20%），每週 50 筆、跑 6 週；固定 10% 抽檢 vs 動態規則（上週抽檢失敗率 > 10% → 本週提高到 50%；在 50% 下整週抽不到錯 → 降回 10%）。兩種規則用同一組「抽檢籤」，所以動態抓到的錯一定不少於固定。結果寫到 ch05/interactive/monitor_sampling.json，給第 7 步的報告用。

**要跑的內嵌 Python**：

```python
import json
import os
import random

random.seed(55)
OUT = "ch05/interactive"
os.makedirs(OUT, exist_ok=True)
N, P_ERR = 200, 0.08
bad = [random.random() < P_ERR for _ in range(N)]
true_n = sum(bad)
true_p = true_n / N
print(f"{N} 筆假交接，每筆 {P_ERR:.0%} 機率內容錯誤 → 這一批實際錯了 {true_n} 筆（{true_p:.1%}）")
print(f"只靠微觀確認：{N} 筆都回了「收到、理解、開始做」，靠確認訊息抓到的錯：0 筆")
print()
print(" 抽檢率 | 抽幾筆 | 抓到錯 | 估計錯誤率 | 漏到下游的錯")
print("-" * 58)
once = []
for rate in (0.10, 0.30):
    k = round(N * rate)
    pick = random.sample(range(N), k)
    caught = sum(1 for i in pick if bad[i])
    once.append({"rate": rate, "sampled": k, "caught": caught, "estimate": round(caught / k, 4), "leaked": true_n - caught})
    print(f" {rate:>6.0%} | {k:>6} | {caught:>6} | {caught / k:>10.1%} | {true_n - caught:>12}")
print()
print("同一批交接，每種抽檢率各重抽 1,000 次：估計錯誤率會跳多大？")
print(" 抽檢率 | 平均估計 | 標準差   | 最低 | 最高 | 偏離真值超過 4 個百分點")
print("-" * 70)
spread = []
for rate in (0.10, 0.30):
    k = round(N * rate)
    ests = []
    for _ in range(1000):
        pick = random.sample(range(N), k)
        ests.append(sum(1 for i in pick if bad[i]) / k)
    mean = sum(ests) / len(ests)
    sd = (sum((e - mean) ** 2 for e in ests) / len(ests)) ** 0.5
    off = sum(1 for e in ests if abs(e - true_p) > 0.04) / len(ests)
    lo, hi = min(ests), max(ests)
    spread.append({"rate": rate, "mean": round(mean, 4), "sd_points": round(sd * 100, 2), "min": lo, "max": hi, "off4": off})
    print(f" {rate:>6.0%} | {mean:>8.1%} | {sd * 100:>4.1f} 點  | {lo:>4.0%} | {hi:>4.0%} | {off:>8.0%}")
print()
print("規則：某隊上週抽檢失敗率 > 10% → 本週抽檢率提高到 50%；在 50% 下整週抽不到錯 → 降回 10%")
TEAMS = [("A 隊", 0.03), ("B 隊", 0.05), ("C 隊", 0.08), ("D 隊", 0.20)]
WEEKS, PER = 6, 50
rng = random.Random(555)
print(" 團隊 | 真實錯誤率 | 6 週總錯數 | 固定 10%：抽／抓／漏 | 動態規則：抽／抓／漏 | 動態每週抽檢率")
print("-" * 100)
teams_out = []
tot = [0, 0, 0, 0, 0]
for name, p in TEAMS:
    weeks = [[(rng.random() < p, rng.random()) for _ in range(PER)] for _ in range(WEEKS)]
    total_bad = sum(1 for w in weeks for b, u in w if b)
    fs = sum(1 for w in weeks for b, u in w if u < 0.10)
    fc = sum(1 for w in weeks for b, u in w if b and u < 0.10)
    rate, ds, dc, plan = 0.10, 0, 0, []
    for w in weeks:
        plan.append(rate)
        s = sum(1 for b, u in w if u < rate)
        c = sum(1 for b, u in w if b and u < rate)
        ds += s
        dc += c
        fail = c / s if s else 0.0
        if fail > 0.10:
            rate = 0.50
        elif rate == 0.50 and c == 0:
            rate = 0.10
    plan_s = "/".join(str(round(x * 100)) for x in plan) + "%"
    teams_out.append({"team": name, "p": p, "total_bad": total_bad, "fixed": [fs, fc, total_bad - fc],
                      "dynamic": [ds, dc, total_bad - dc], "plan": plan_s})
    tot = [tot[0] + total_bad, tot[1] + fs, tot[2] + total_bad - fc, tot[3] + ds, tot[4] + total_bad - dc]
    print(f" {name} | {p:>10.0%} | {total_bad:>10} | {fs:>5}／{fc:>3}／{total_bad - fc:>3}     | {ds:>5}／{dc:>3}／{total_bad - dc:>3}     | {plan_s}")
print()
print(f"合計：總錯 {tot[0]} 筆；固定 10% 抽了 {tot[1]} 筆、漏掉 {tot[2]} 筆；動態規則抽了 {tot[3]} 筆、漏掉 {tot[4]} 筆")
print("微觀確認只保證「有溝通」；品質要靠中觀抽檢補，抽檢資源再集中到出錯多的團隊。")
with open(OUT + "/monitor_sampling.json", "w", encoding="utf-8") as f:
    json.dump({"n": N, "p_err": P_ERR, "true_bad": true_n, "once": once, "spread": spread,
               "teams": teams_out, "totals": tot}, f, ensure_ascii=False, indent=2)
print("已寫入 " + OUT + "/monitor_sampling.json")
```
